# عقارك أونلاين — Aqarak Online

منصة إعلانات عقارية باللغة العربية أساسًا، مع إمكانية التحويل للإنجليزية.
المستخدم يعرض شقة / بيت / عمارة / محل / فيلا للبيع أو للإيجار، ويتصفح الإعلانات المتاحة،
والشراء أو الاستئجار يتطلب تسجيل الدخول. الأدمن يتابع طلبات التواصل ويرد عليها.

## المميزات

- التسجيل والدخول برقم الموبايل الموثَّق: التسجيل يتطلب الاسم والعنوان ورقم الموبايل
  (مصري يبدأ بـ 01)، ثم تأكيد الرقم بكود من 6 أرقام صالح 10 دقائق، ولا يُسمح بالدخول
  قبل التأكيد. الدخول يتم برقم الموبايل وكلمة المرور، وليس بالإيميل.
  الإيميل في التسجيل اختياري، ويُستخدم فقط لمعرفة حساب الأدمن (إذا طابق `AdminEmail`).
- إرسال كود التأكيد: الافتراضي مزود `Log` يكتب الكود في لوج التطبيق للتجربة ولا يرسل
  رسالة حقيقية. لإرسال SMS حقيقي اضبط `Sms:Provider` على `Twilio` مع بيانات Twilio
  (انظر قسم الإعدادات). لا تضع مفاتيح SMS حقيقية في `appsettings.json` داخل ريبو عام؛
  استخدم متغيرات البيئة أو `dotnet user-secrets`.
- إعلانات: للبيع / للإيجار، النوع (شقة، بيت، عمارة، محل، فيلا)، المنطقة، المساحة
  بالمتر المربع، التفاصيل، المميزات (سطر لكل ميزة)، السعر المبدئي، رقم إعلان يتولد
  تلقائيًا (AQ-0001، AQ-0002...)، وصورة اختيارية.
- عدد المشاهدات: يظهر في كارت الإعلان وفي صفحة التفاصيل، ويزيد عند مشاهدة صفحة
  التفاصيل من زائر عادي (لا يُحسب مشاهدة الأدمن ولا صاحب الإعلان).
- الصفحة الرئيسية: قسم "من نحن" وقسم "ليه تختارنا؟" (أسرع طريقة للبيع والشراء والإيجار،
  تتابع بنفسك وتختار الأفضل، عمولة على قد إيدك، لا لاستغلال السماسرة والبوابين)،
  ثم أحدث الإعلانات المتاحة.
- الإتاحة يحددها الأدمن: أعلى كارت الإعلان يظهر بوضوح "متاح" أو "غير متاح"، والأدمن
  يستطيع إغلاق الإعلان أو إعادة إتاحته من صفحة "كل الإعلانات". الإعلان غير المتاح لا يظهر
  فيه زر "تواصل معنا" في الكارت ولا في صفحة التفاصيل، ولا يمكن الاستعلام عنه
  (صفحة التواصل ترفضه أيضًا من جهة السيرفر).
- مراجعة الأدمن قبل النشر: أي إعلان جديد من مستخدم عادي يبقى معلّقًا ولا يظهر للعامة
  حتى يوافق عليه الأدمن من صفحة "كل الإعلانات" (موافقة / رفض). تعديل مستخدم عادي
  لإعلانه يعيده للمراجعة. إعلانات الأدمن نفسه تُنشر فورًا، والأدمن يستطيع إضافة عقار
  من نفس نموذج إضافة الإعلان.
- خصوصية بيانات المعلن: صفحة الإعلان العامة لا تعرض اسم المعلن أو رقمه أو عنوانه.
  هذه البيانات تظهر للأدمن فقط في صفحة "كل الإعلانات" وفي صفحة تفاصيل الإعلان
  عندما يفتحها الأدمن. التواصل مع المشتري يتم عبر أرقام الموقع (الهاتف / واتساب)
  وليس عبر رقم المعلن الشخصي.
- بحث وفلترة: بالعنوان أو المنطقة، وبالنوع، وبالسعر، والمتاح فقط، ولا تظهر في
  البحث العام إلا الإعلانات المقبولة من الأدمن.
- أدوار: مستخدم (User) وأدمن (Admin). إنشاء / تعديل / حذف الإعلان لصاحبه أو للأدمن فقط.
- زر "تواصل معنا": يفتح صفحة تواصل فيها رقم الهاتف ورقم الواتساب، ونموذج باسم المشتري
  ورقمه ورسالته. الطلب يُحفظ في قاعدة البيانات للأدمن، وصفحة النجاح تعرض رابط واتساب
  جاهزًا (`wa.me`) فيه بيانات المشتري ورقم الإعلان والغرض (شراء / استئجار / استفسار).
- صفحة الأدمن: قائمة طلبات التواصل، زر "تم الرد"، ورابط واتساب مباشر لرقم المشتري،
  وقائمة كل الإعلانات مع إغلاق الإعلان عند إتمام البيع / التأجير.
- اللغة: العربية هي الافتراضي (RTL)، وزرار في الأعلى للتحويل للإنجليزية.
  نصوص الإعلانات نفسها لا تُترجم، لأنها بيانات يدخلها المستخدم.

## ملحوظة مهمة عن واتساب

السيرفر لا يرسل رسالة واتساب بنفسه من غير WhatsApp Business API.
التصميم الحالي يستخدم رابط `wa.me` يفتح محادثة جاهزة للإرسال من هاتف المشتري،
وفي نفس الوقت يحفظ الطلب للأدمن ليتابعه ويرد عليه. هذا هو السلوك المتفق عليه.

## التشغيل

```bash
dotnet run
```

ثم افتح الرابط الذي يطبعه الأمر (عادة `http://localhost:5000`).

قاعدة البيانات SQLite ملف `aqarak.db` يُنشأ تلقائيًا عند أول تشغيل مع بيانات تجريبية
(4 إعلانات عربية مقبولة من الأدمن) وأدوار Admin/User. هذا للتجربة السريعة (EnsureCreated)؛
قبل الإنتاج أنشئ Migration بـ `dotnet ef` واستبدل `EnsureCreated` بـ `Migrate`.

> مهم عند التحديث: `EnsureCreated` لا يضيف أعمدة جديدة لقاعدة بيانات موجودة.
> بعد إضافة حقول جديدة (مثل العنوان وكود التأكيد وحالة الموافقة والمساحة وعدد المشاهدات)، احذف ملف `aqarak.db`
> القديم قبل تشغيل النسخة الجديدة، فيُعاد إنشاؤه بالشكل الجديد مع البيانات التجريبية.
> هذا آمن في التطوير فقط؛ قاعدة بيانات فيها مستخدمون حقيقيون تحتاج Migration.

## الإعدادات المطلوبة قبل الاستخدام الحقيقي

في `appsettings.json` غيّر القيم الافتراضية:

```json
{
  "AdminEmail": "ضع هنا إيميل حساب الأدمن",
  "Contact": {
    "Phone": "+20xxxxxxxxxx",
    "WhatsApp": "+20xxxxxxxxxx",
    "Email": "contact@example.com"
  }
}
```

- سجّل حسابًا برقم موبايل موثَّق، وأدخل الإيميل الموجود في `AdminEmail` في حقل الإيميل
  الاختياري عند التسجيل، ثم أكّد رقم الموبايل بالكود، وسيُمنح دور Admin بعد التأكيد
  (وأيضًا عند إعادة تشغيل التطبيق إذا كان الحساب موجودًا بالفعل).
  لا يوجد مستخدم أدمن مُنشأ بكلمة مرور داخل الكود.
- إذا تركت `AdminEmail` فارغًا، لن يُمنح أحد دور Admin تلقائيًا.
- إعدادات SMS في `appsettings.json`:
  ```json
  {
    "Sms": {
      "Provider": "Log",
      "TwilioAccountSid": "",
      "TwilioAuthToken": "",
      "TwilioFromNumber": ""
    }
  }
  ```
  غيّر `Provider` إلى `Twilio` واملأ البيانات الثلاثة لإرسال رسائل حقيقية،
  ويفضَّل تمريرها كمتغيرات بيئة (`Sms__TwilioAuthToken` مثلًا) لا كقيم في الملف المرفوع.

## التقنية

- ASP.NET Core MVC على .NET 8 (حتى يمكن بناء المشروع والتحقق منه في البيئة المتاحة).
  الترقية إلى .NET 9 أو 10 لاحقًا تتم بتغيير `TargetFramework` وإصدارات الحزم في ملف المشروع.
- ASP.NET Core Identity (أدوار + كوكيز)، Entity Framework Core مع SQLite.
- للتحويل إلى SQL Server: غيّر حزمة SQLite إلى SqlServer، وبدّل `UseSqlite` بـ `UseSqlServer`
  في `Program.cs`، وعدّل سلسلة الاتصال في `appsettings.json`.
